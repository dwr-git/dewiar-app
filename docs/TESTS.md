# Проверки Dewiar — как устроены и как с ними работать

Около тысячи проверок — главная страховка проекта. Каждая ошибка, которую нашёл человек, становится проверкой. Каждый
сценарий экзамена, который пришлось чинить в программе, — тоже. Поэтому они не должны теряться: новая беседа поднимает
проект и сразу видит, всё ли цело. Полный список с описанием каждой проверки собирает `python3 tools/tests_list.py
<файл.md>`: в аварийном архиве он лежит готовым как `TESTS_LIST.md`.

## Где что

| Что | Где |
|---|---|
| сами проверки | `tests/*_test.py` — около 1000 файлов; одна проверка — один файл, запускается отдельно: `python3 tests/x_test.py` |
| быстрый прогон | `tests/run_quick.sh` — почти все проверки (≈880), без звука и тяжёлых моделей; около часа на 2 ядрах |
| полный прогон | `tests/run_all.sh` — ещё ≈120 проверок со звуком, моделями и долгими сценариями |
| только задетые изменением | `tests/run_changed.sh [метка]` — выбирает по карте `tests/impact.json`; перед каждым выпуском |
| карта «проверка → что читает» | `tests/impact.json` и `tests/impact.fn.json.gz` (по функциям Python); строит `tools/test_impact.py build <папка записи>` |
| эталоны | `tests/snap/` — снимок команд, инструментов, подсказок (`core_snap_test.py --update` — после намеренного изменения) |
| подставные сервисы | `tests/mock_llm.py` (модель), `task_mock.py`, `fake_site/`, `fake_billing.php`, `fake_docker.py`, `mcp_test_server.py`, `proxykit.py` |
| данные | `tests/fixtures/`, `tests/silence90.wav`, `make_audio.py` (речь из espeak-ng) |
| база как на сайте | `tests/pg_temp.sh` — временный PostgreSQL, если есть `initdb`; нет — раздел с базой пропускается |

## Как читать результат

Проверка печатает строки `✅ …` и `❌ …`; пройдена — если нет ни одной ❌, код выхода 0 и есть хоть одна ✅ (или
«ALL OK»). Прогон в конце пишет `ИТОГ: всё прошло` или `ИТОГ: провалов N`. Строка `⏭ ПРОПУСК: …` — проверке не хватает
внешнего (модели Vosk, браузера, базы); это не провал, причина написана рядом.

При `DEWIAR_JOBS=2` (две проверки сразу) упавшая в толпе перепроверяется одна: «со второго раза, одна» — значит, мешала
нагрузка. Под нагрузкой иногда моргают `cloud_runner`, `hold_dictation`, проверки игр и анимаций — перепроверить отдельно.

## Как работаем

1. **Ошибка человека → проверка.** Имя — по смыслу и дате или номеру: `stop_media1120_test.py`, `mac_net908_test.py`.
   В начале файла — docstring: что сломалось у человека (его словами, с номером жалобы) и что теперь должно быть.
   Регистрация — строка `run "что проверяет (откуда)" $PY "$T/имя_test.py"` в `tests/run_quick.sh` (рядом с похожими).
2. **Поведение модели → ещё и сценарий экзамена** (`data/exam/scenarios.json`, телефон — `android/assets/www/exam.js`).
3. **Перед выпуском** — `bash tests/run_changed.sh` (всё зелёное). **После выпуска, в фоне** —
   `DEWIAR_TRACE_DIR=<папка> DEWIAR_JOBS=2 bash tests/run_quick.sh`, затем `python3 tools/test_impact.py build <папка>`
   и новую карту — в коммит (без свежей карты новые проверки выбираются хуже).
4. **Не трогать файлы рабочей копии, пока в ней идёт прогон** (проверки читают код на ходу). Новую работу — в отдельной
   копии: `git worktree add ../wNN -b wNN HEAD`.
5. **Изменилось поведение намеренно** — поправить ожидание в проверке и написать рядом, почему (дата, кто попросил).

## Что нужно, чтобы проверки шли

Всё ставит `bash tools/setup_env.sh`: Python-библиотеки (`requirements.txt`), PHP с SQLite, ffmpeg, espeak-ng,
Node.js (проверки приложения телефона и страниц), Playwright с Chromium (окна виджета, студии, телефона), инструменты
сборки Android. Модель Vosk (`vosk-model-small-ru-0.22.zip`, 45 МБ) ядро скачивает само; если сайт модели закрыт —
положить zip в `data/` (или указать адрес в `DEWIAR_VOSK_URL`), иначе проверки слуха будут «пропущены».

## Откуда берётся время прогона

Проверок много, а в рабочей среде 2 ядра. `run_changed.sh` выбирает только задетые: для Python — по функциям (правка
одной функции тянет только её проверки). С 1.0.50 — и для JS: телефон (`android/assets/www/app.js` и его части
`android/www-src/app/*.js`), виджет (`ui/hud.html`), общие скрипты `ui/assets/*.js`. Запись прогона снимает покрытие V8
в браузере проверки (Playwright → CDP) и в node (`NODE_V8_COVERAGE`): «jsfn:файл::функция» — выполнилась, «jscov:файл» —
покрытие снято. Правка внутри функции верхнего уровня тянет только проверки, что её выполняли (и что читают исходник
текстом и называют изменённое); константа — проверки функций, где она названа. Код верхнего уровня, разметка и стили
`hud.html`, проверка без покрытия файла — по-старому, по файлу. Работает после первого полного прогона с записью
(карта без «jscov» — тоже по файлу). Проверка механизма — `tests/impact_js1120_test.py`. Правки общих мест
(`core/engine_base.py`, ход разговора) тянут почти всё.
