# Навык: тесты — подтвердить правильность кода запуском

> Написать и запустить тесты (pytest или assert-скрипт), проверить крайние случаи и убедиться, что код действительно работает, а не «выглядит правильным».

Результат без прогона тестов — это гипотеза, а не результат.

## Как запускать
- **pytest** (предпочтительно): файлы `test_*.py`, функции `test_*`, проверки через
  `assert`. Запуск: `python -m pytest -q`. Если pytest не установлен —
  `pip install pytest --break-system-packages`, затем снова.
- **Без установки**: обычный скрипт с `assert` и `print('OK')`, запуск `python check.py`.
  Тоже полностью годится для быстрой проверки.

```python
# test_calc.py
from calc import add

def test_basic():
    assert add(2, 3) == 5

def test_edge():           # крайние случаи важнее «счастливого пути»
    assert add(-1, 1) == 0
    assert add(0, 0) == 0
```
```bash
python -m pytest -q          # -q кратко; -x остановиться на первом падении; -k 'имя' выбор
```

## Что покрывать
1. **Счастливый путь** — типичный корректный вход.
2. **Границы** — пусто, ноль, один элемент, максимум, отрицательные, очень длинное.
3. **Плохой вход** — None, не тот тип, битые данные: ожидается понятная ошибка,
   а не тихий неверный результат.
4. **Регресс** — на найденный баг пиши тест, который его ловит, ЧТОБЫ не вернулся.

## Правила
- Сначала прогоняй тесты и убеждайся, что они действительно проверяют (упади нарочно).
- Числа с плавающей точкой сравнивай с допуском: `abs(a-b) < 1e-9` (или `pytest.approx`).
- Тест должен быть детерминированным: фиксируй seed, не завись от времени/сети.
- После любой правки кода — перезапусти тесты (см. скилл debugging).
