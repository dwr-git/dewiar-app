> Написание кода с петлёй верификации: запуск → тесты → рефакторинг → проверенный результат.

# Скил: кодинг с верификацией

ЗОЛОТОЕ ПРАВИЛО: код, который ты не запускал, — не существует. Любой код для
пользователя проходит петлю: НАПИСАЛ → ЗАПУСТИЛ → ПРОТЕСТИРОВАЛ → ИСПРАВИЛ →
(повторяй до зелёного) → ОТРЕФАКТОРИЛ → отдал.

## Петля верификации (по шагам)

1. **Пойми задачу и краевые случаи.** В plan.md выпиши: входы/выходы, краевые
   случаи (пусто, ноль, отрицательные, кириллица, большие данные), критерии готовности.

2. **Напиши код файлом**, не в голове: `write_file` → `solution.py` (черновик —
   в корне сессии, в outputs/ попадёт только проверенная версия).

3. **Сразу запусти** на простом примере. Ошибка? Прочитай traceback ЦЕЛИКОМ,
   исправь причину (не симптом), запусти снова.

4. **Тесты — pytest уже установлен.** Пиши тесты файлом и гоняй:
   ```python
   # write_file: test_solution.py
   import pytest
   from solution import validate_email

   def test_basic():        assert validate_email('a@b.ru') is True
   def test_no_at():        assert validate_email('ab.ru') is False
   def test_empty():        assert validate_email('') is False
   def test_cyrillic():     assert validate_email('тест@почта.рф') is True
   ```
   ```python
   import subprocess
   r = subprocess.run(['python','-m','pytest','test_solution.py','-v','--tb=short'],
                      capture_output=True, text=True)
   print(r.stdout[-3000:]); print(r.stderr[-800:])
   ```
   Красные тесты → чини код (или тест, если ошибся тест) → перезапускай.
   ЧИНИ ТОЧЕЧНО инструментом edit (старый фрагмент → новый), а не перезаписью
   всего файла — перезапись большого файла обрежется по лимиту токенов.
   Минимум: happy path + 2–3 краевых случая на каждую публичную функцию.

5. **Рефакторинг после зелёного:** убери дубли, дай понятные имена, добавь
   докстринги и типы. После рефакторинга — тесты ещё раз (они защищают от поломки).

6. **Выдача:** скопируй в outputs/ финальный код + тесты; в final_answer — что
   сделано, как запустить, вывод тестов (`N passed`).

## Отладка чужого кода (просили «найди баг / почини»)
1. Сначала ВОСПРОИЗВЕДИ баг: запусти код, получи ошибку/неверный результат.
2. Локализуй print'ами или минимальным примером.
3. Почини, затем напиши тест, который ловил бы этот баг, — и покажи, что теперь зелёный.

## Частые грабли
- Бесконечный ввод: никаких `input()` — параметры через аргументы/константы.
- Случайность в тестах: фиксируй `random.seed(42)`.
- Файлы в тестах: создавай временные через `tmp_path` (фикстура pytest).
- Сравнение float: `pytest.approx(x, rel=1e-6)`.
- Долгие тесты: таймаут запуска ограничен — тестируй на малых данных.
- HTML/JS код запусти проверкой синтаксиса хотя бы: `node --check file.js`
  (если node нет — install apt nodejs) или валидируй структуру тегов кодом.

## Если просили «программу с нуля» (CLI/модуль)
Структура выдачи в outputs/: `main.py` (или пакет), `test_main.py`,
`README.md` (3–6 строк: что делает, как запустить, пример). Это уровень,
которым не стыдно поделиться.
