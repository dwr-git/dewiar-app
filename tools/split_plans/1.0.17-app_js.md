# 1.0.17 — телефон по частям: app.js → android/www-src/app

**Как устроено.** Исходник интерфейса телефона и веб-версии — 20 частей `android/www-src/app/NN-имя.js` по разделам
«/* ---------- … ---------- */», которые уже были в app.js. `android/assets/www/app.js` собирается склейкой частей
(`python3 tools/app_join.py`) — тем же одним файлом и одним `<script>`, что раньше; первая строка — пометка «собран из
частей». Части в приложение и веб-версию не попадают (они вне `assets/www`); `www_assemble.sh` не соберёт www, если
app.js разошёлся с частями.

**Почему не несколько `<script>`.** Проверено разбором (acorn): функции-объявления поднимаются только внутри своего
файла, а обещания, продолжения `await` и таймеры, запущенные при загрузке, выполнялись бы между файлами — раньше, чем
загрузились следующие части (у одного файла такого нет). Примеры: `featApply()` при загрузке (часть «Досуг») через
`gameClose → openSheet` дотягивается до `courseSeen` (часть курсов), `effProxy` из «Здоровья» нужен настройкам при
загрузке. Склейка снимает вопрос целиком: поведение у людей не меняется.

**Проверено.** Склейка частей без шапок = прежний app.js байт в байт (1 152 438 байт); `tests/app_parts_test.py`
(склейка, шапки, разрезы по разделам, части не в сборке); проверки телефона и веб-версии (android_*, web*, phone*),
старый Safari (web_oldsafari1028), Mac (mac1104, mac_gatekeeper1115 — программа для Mac app.js не использует).
Проверки, читающие app.js текстом, работают как раньше: app.js на месте.

**Править дальше:** часть в `android/www-src/app/`, затем `python3 tools/app_join.py`; новый раздел — новая часть с
номером (порядок частей = порядок исполнения).
