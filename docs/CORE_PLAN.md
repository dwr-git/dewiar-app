## Правила на всё время

1. **Поведение не меняется.** Перестройка — отдельно от исправлений. Коммит «переложил» не содержит «поправил».
2. **Сначала страховка, потом перенос.** Прежде чем трогать модуль — «снимок поведения» (вход → выход как сейчас) для
   всего, что он отдаёт наружу. Перенос обязан его не менять.
3. **Маленькие шаги.** Один модуль — один коммит; после каждого — быстрый набор проверок. Сломалось — откат одного
   коммита, а не выпуска.
4. **Старые имена живут, пока на них ссылаются.** Переносим с прослойкой (`from tools_fs import *` в старом месте),
   убираем прослойку последним коммитом выпуска, когда поиск по проекту и проверки показывают, что ссылок нет.
5. **Мёртвое убираем только доказанно мёртвое:** нет вызовов в коде, в строках-именах (реестры, `getattr`), в UI-командах,
   в телефоне и на сервере. Сомнение — оставить и пометить.
6. **Новых функций нет**, кроме исправления ошибок людей (они идут отдельными коммитами с проверкой в `tests/`).
7. Каждый выпуск — полный прогон `run_quick.sh`, экзамен владельца по желанию, карта модулей в `docs/HANDOFF.md`.

## Шаг 0 — страховка (до 1.0.8)

- `tools/core_map.py` — карта: модули, кто кого импортирует, размеры, команды (`cmd == "…"`) и действия (`TOOLS`) с
  местом определения и использования (ядро, студия, телефон, сервер). Кандидаты в мёртвое — с доказательством «нигде».
- `tests/snap/` — снимки поведения: для каждого действия из `TOOLS` — описание и схема параметров (что видит модель);
  для каждой команды — что возвращает на типовом входе с поддельным движком; для подсказок ответа — какие фразы что
  включают. Один файл-эталон, проверка сравнивает.
- `tests/run_fast.sh` — быстрый набор (2–3 мин): снимки + проверки без окон и без запуска ядра целиком.

## 1.0.8 — действия модели

`core/tools.py` → пакет `core/tools/`: `registry.py` (TOOLS, Toolbox, политика), и по смыслу — `fs.py`, `remind.py`,
`web.py`, `docs.py`, `media.py`, `system.py`, `money.py`, `sites.py`, `plugins.py`, `notes.py`. Описания действий — рядом
с кодом действия. Снимок `TOOLS` (имена, описания, схемы, уровни) — байт в байт тот же.

## 1.0.9 — ответ

`engine_answer.py`: подсказки к вопросу (`*_RX` + текст) → реестр правил `core/hints/` (одно правило — регулярка, условие,
текст, номер жалобы, проверка); проверки после ответа (`quality.py`) — тем же реестром. Сам ответ — конвейер шагов
(понять → подсказки → модель → проверки → голос) с понятными границами. Экзамен до и после — оценки не ниже.

## 1.0.10 — команды и сайт

`engine_commands.py` → команды по модулям с реестром `@command("tg_get")`; `cloud.php` → `server/dwrapp/cloud/*.php` по
разделам (API, кабинет, оплата, сеть, сайты) с тем же входом `cloud.php`. Телефон (`app.js`) — следующим кругом.

## Как понять, что стало лучше

- самый большой файл ядра — меньше 1500 строк; у каждого модуля — одна задача в первой строке описания;
- быстрый набор — до 3 минут, полный — без изменений по составу;
- мёртвое — убрано со ссылкой на доказательство в коммите;
- в `docs/HANDOFF.md` — карта модулей вместо истории по версиям.
