> Интерактивные визуализации (графики, схемы, графы, дашборды) в HTML: какие библиотеки и КАК подключать, чтобы они точно отрисовались.

# Скил: интерактивная визуализация в HTML

Когда нужен НЕ статичный рисунок, а интерактив (зум, ховер, переключение рядов,
живой дашборд, схема, граф) — делай это в `outputs/*.html`. Но подключение
библиотек в этой среде имеет ловушку. Прочитай раздел «Как подключать» — иначе
страница откроется пустой.

## 👁 КАК СМОТРЕТЬ СВОЙ HTML (важно, иначе потеряешь шаги)
Только `screenshot {"path":"outputs/файл.html"}` — он рендерит локальный файл в
настоящем браузере вместе с твоими скриптами и стилями.
- `browser` открывает ТОЛЬКО внешние адреса http/https — локальный файл он не
  откроет, это не ошибка файла.
- НЕ поднимай веб-сервер (`python -m http.server`, `npx serve` и т.п.): он
  остаётся в фоне, занимает порт, следующая попытка падает с «Address already in
  use», и ты застрянешь на переборе портов. Это никогда не нужно.

## 📚 БИБЛИОТЕКИ: БЕРИ ГОТОВЫЕ, НЕ КАЧАЙ

В системе уже лежат локальные копии библиотек. Подключай их ТАК:

```html
<script src="js/echarts.min.js"></script>
```

Точный список доступных файлов система сообщает в системном промпте строкой
«ГОТОВЫЕ JS-БИБЛИОТЕКИ» — сверяйся с ней, имена бери оттуда, не угадывай.
Обычно это echarts, plotly, chart.js, mermaid, vis-network, jsplumb, katex,
marked, highlight, model-viewer.

Правила:
- **НЕ скачивай библиотеки** (`wget`, `pip`, `curl` за библиотекой) — они уже есть.
- **НЕ подключай CDN** — при рендере он недоступен, график выйдет пустым.
- Даже если случайно указал CDN-адрес известной библиотеки, система подставит
  локальную копию сама. Но правильно писать сразу `js/<имя>`.
- Нужной библиотеки нет в списке? Скажи об этом в ответе и сделай статичный
  график через matplotlib — не изобретай обходные пути.

## 📐 ПОЧЕМУ ГРАФИК ВЫХОДИТ ПУСТЫМ (вторая частая причина)

ECharts, Plotly, Chart.js рисуют внутрь контейнера и берут его РАЗМЕР. Если у
контейнера нет явной высоты в пикселях, высота = 0, и блок остаётся пустым —
при полностью правильном коде.

**Всегда задавай высоту в пикселях:**

```html
<div id="chart" style="width:100%;height:420px"></div>
```

Нельзя: `height:100%`, `height:50vh` внутри блока без высоты, или вообще без
height. Проверь это ПЕРВЫМ делом, если зона графика пустая.

### ⚠️ ТОЧНЫЕ ИМЕНА ФУНКЦИЙ (частая ошибка — выдуманный метод)

Библиотека может быть подключена правильно, но вызов с несуществующим методом
даёт пустой график и ошибку в консоли. Правильные вызовы — ровно такие:

| Библиотека | Единственно верный вызов |
|---|---|
| Plotly | `Plotly.newPlot(idИлиЭлемент, data, layout)` |
| ECharts | `echarts.init(el).setOption(option)` |
| Chart.js | `new Chart(canvasEl, {type, data, options})` |
| Mermaid | `mermaid.initialize({startOnLoad:true})` |
| vis-network | `new vis.Network(el, data, options)` |

Не существует: `Plotly.new`, `Plotly.plot(...)` как основной способ,
`echarts.setOption(...)` без `init`, `Chart.create(...)`.
Сомневаешься — используй шаблон ниже дословно, меняя только данные.

### Рабочие шаблоны

**ECharts:**
```html
<div id="c1" style="width:100%;height:420px"></div>
<script src="js/echarts.min.js"></script>
<script>
  const ch = echarts.init(document.getElementById('c1'));
  ch.setOption({
    tooltip:{trigger:'axis'}, legend:{}, xAxis:{type:'category', data:[1,2,3]},
    yAxis:{type:'value'}, series:[{type:'line', data:[5,9,4]}]
  });
  window.addEventListener('resize', () => ch.resize());
</script>
```

**Plotly:**
```html
<div id="c2" style="width:100%;height:420px"></div>
<script src="js/plotly-3.3.1.min.js"></script>
<script>
  Plotly.newPlot('c2', [{x:[1,2,3], y:[5,9,4], type:'scatter'}],
                 {margin:{t:30}}, {responsive:true});
</script>
```

**Chart.js** (нужен `<canvas>`, а не `<div>`):
```html
<div style="height:420px"><canvas id="c3"></canvas></div>
<script src="js/chart.js"></script>
<script>
  new Chart(document.getElementById('c3'), {
    type:'line',
    data:{labels:[1,2,3], datasets:[{label:'ряд', data:[5,9,4]}]},
    options:{responsive:true, maintainAspectRatio:false}
  });
</script>
```

**Mermaid** (схемы):
```html
<pre class="mermaid">graph TD; A-->B; B-->C;</pre>
<script src="js/mermaid.min.js"></script>
<script>mermaid.initialize({startOnLoad:true});</script>
```

### ОБЪЁМ ДАННЫХ — частая причина «пустого» графика

Много точек = страница долго рисуется, и снимок застаёт её незаконченной.
Выглядит как «библиотека не работает», хотя дело только в объёме.

- **Не больше ~200–300 точек на линию.** Больше — прорежай:
  `data[::max(1, len(data)//250)]`.
- Округляй числа до 2–3 знаков: `round(v, 3)` — файл станет в разы меньше.
- Держи готовый HTML **до ~300 КБ**. Больше — сокращай данные, а не надейся, что успеет отрисоваться.
- Если данных правда много (тысячи точек) — делай статичный PNG через
  matplotlib: он отрисуется гарантированно.

**ВАЖНО про диагностику:** если график пустой, не меняй библиотеку наугад.
Проверь по порядку: (1) высота контейнера в пикселях, (2) объём данных,
(3) локальный путь `js/…` вместо CDN. Смена библиотеки почти никогда не
является причиной — ECharts, Plotly и Chart.js работают одинаково хорошо.

### Ещё три правила, без которых бывает пусто
1. **Скрипты — в конце `<body>`** или инициализация после того, как `<div>` уже
   существует в разметке. Инициализация до появления контейнера = пустой блок.
2. **Данные встраивай прямо в HTML** (`const data = [...]`). Любой `fetch()`
   локального файла при рендере не сработает.
3. **Одна страница — один способ.** Не смешивай ECharts и Plotly на одном
   графике и не инициализируй один контейнер дважды.

## ⛔ ГЛАВНОЕ ПРАВИЛО (иначе графики будут пустыми)
Скриншот/просмотрщик рендерят страницу на компьютере БЕЗ интернета. Поэтому:
1. **Нужен просто график/диаграмма/дашборд БЕЗ явной просьбы про интерактив** →
   рисуй в `matplotlib`, сохрани PNG в `outputs/`, вставь `<img src="chart.png">`.
   Работает ВСЕГДА, виден на скриншоте с первого раза, без JS. **Это выбор по
   умолчанию.** Не превращай «построй диаграммы» в интерактивный JS-дашборд по
   своей инициативе — это лишние шаги и риск пустых графиков.
2. **Интерактив (зум/ховер/переключатели) делай ТОЛЬКО если пользователь прямо
   просил** «интерактивный / с зумом / кликабельный». Тогда СКАЧАЙ библиотеку в
   `outputs/` через python и сошлись ОТНОСИТЕЛЬНО (пример ниже). CDN
   `<script src="https://…">` не использовать. Библиотеку бери НЕБОЛЬШУЮ (echarts
   ~1 МБ ок; не вшивай plotly.js на 4-5 МБ — тяжёлый файл долго рендерится и
   скриншот застаёт пустоту).
3. Проверь полностраничным `screenshot`. Пусто → сначала проверь: та ли библиотека
   подключена локально, верны ли имена колонок/данные, нет ли ошибки в JS-структуре.
4. **АНТИ-ЗАЦИКЛИВАНИЕ (важно!):** если после **2 попыток** починки скриншот всё
   ещё показывает пустые графики, НО HTML/JS структурно корректен (библиотека
   подключена локально, данные встроены, ошибок в консоли нет) — **НЕ переделывай
   в третий раз**. Скриншот-рендерер иногда не успевает отрисовать тяжёлый JS, а
   у пользователя в браузере всё откроется. В этом случае: либо сделай надёжный
   вариант с matplotlib-PNG и заверши, либо заверши как есть, ОДНОЙ фразой
   предупредив пользователя «графики интерактивные, откроются в вашем браузере».
   Не трать 30+ шагов на борьбу со скриншотом.
5. **ДАННЫЕ встраивай ПРЯМО в HTML** как JS-переменную (`const data = {...}`) или в
   `<script id="data" type="application/json">…</script>`. **НЕ загружай их через
   `fetch('data.json')` / XMLHttpRequest** — на компьютере локальный fetch не работает,
   график останется пустым. Данные лежат в файле сессии → прочитай их python'ом и
   впиши в HTML при генерации.

## Сначала реши: нужен ли вообще интерактив
- Один статичный график (одна картинка в отчёт) → ПРОЩЕ и надёжнее `matplotlib`,
  сохрани PNG в `outputs/` и вставь `<img>` / покажи через show. Не тяни JS-библиотеку ради одного бар-чарта.
- Нужен зум/ховер/переключатели/живой дашборд/схема/граф → бери JS-библиотеку (ниже).

## Как подключать библиотеку (ВАЖНО — иначе не отрисуется)
Твой HTML открывается у пользователя в песочном iframe: относительные ссылки
переписываются на ФАЙЛЫ ТЕКУЩЕЙ СЕССИИ, а общая папка `/js` сайта оттуда недоступна.
Поэтому НАДЁЖНЫЙ путь — **скачать библиотеку в `outputs/` своими руками** (у тебя
есть интернет на компьютере) и сослаться на неё ОТНОСИТЕЛЬНО:

```python
import os, urllib.request
os.makedirs('outputs', exist_ok=True)
LIB = {
  'echarts.min.js'      : 'https://cdn.jsdelivr.net/npm/echarts/dist/echarts.min.js',
  'plotly.min.js'       : 'https://cdn.jsdelivr.net/npm/plotly.js-dist-min/plotly.min.js',
  'mermaid.min.js'      : 'https://cdn.jsdelivr.net/npm/mermaid/dist/mermaid.min.js',
  'vis-network.min.js'  : 'https://cdn.jsdelivr.net/npm/vis-network/standalone/umd/vis-network.min.js',
  'chart.min.js'        : 'https://cdn.jsdelivr.net/npm/chart.js',
}
name = 'echarts.min.js'                       # выбери нужную
urllib.request.urlretrieve(LIB[name], 'outputs/' + name)
print('ok', os.path.getsize('outputs/' + name), 'байт')
```

В HTML ссылайся БЕЗ пути, файл лежит рядом в outputs/:
```html
<script src="echarts.min.js"></script>
```
Просмотрщик сам перепишет это на files.php той же сессии — график отрисуется даже
без интернета у пользователя. (Прямой CDN `<script src="https://…">` — только
запасной вариант: сработает, лишь если интернет открыт в браузере пользователя.)

## Какую библиотеку под что
- **ECharts** — универсальные графики (линии/бары/пироги/heatmap/candlestick), много данных, красивый дефолт. Рабочая лошадка для дашбордов.
- **Plotly** — научные/статистические графики, 3D, экспорт PNG из коробки, удобный зум.
- **Mermaid** — схемы и диаграммы из текста (flowchart, sequence, gantt, state). Идеально для «нарисуй процесс/архитектуру».
- **vis-network** — графы и сети узлов (связи, зависимости, онтологии).
- **Chart.js** — простые лёгкие графики, когда ECharts избыточен.

## Обязательная самопроверка
1. После write_file прочитай файл и проверь целостность:
   ```python
   t=open('outputs/app.html',encoding='utf-8').read()
   print(len(t), '</html>' in t, t.count('{')-t.count('}'))
   ```
2. Большой HTML пиши ЧАСТЯМИ (write_file каркас → дописывай через open(...,'a')).
3. Покажи: `{"tool":"show","args":{"path":"outputs/app.html"}}`.
4. ПОСМОТРИ СВОИМИ ГЛАЗАМИ: `{"tool":"screenshot","args":{"path":"outputs/app.html"}}`.
   Относительные ссылки на ЛОКАЛЬНЫЕ файлы сессии (её js/css/png рядом) теперь
   работают и в этой проверке — так что если график ПУСТ, ищи причину в данных
   или ошибке JS (неверные имена колонок, кривой JSON), а НЕ в относительном пути.
   Пусто при CDN-ссылке → библиотека не загрузилась: скачай её локально (см. выше).
   Почини (edit) → screenshot снова.
5. Только после визуально рабочего графика — final_answer с упоминанием файла.

## Раскладка дашборда: чтобы всё влезло с первого раза
- Ряд однотипных карточек (часы прогноза, метрики, дни) — сетка, которая сама
  переносится: `display:grid; grid-template-columns:repeat(auto-fill,minmax(88px,1fr)); gap:8px`.
  Никаких фиксированных ширин у карточек и `overflow:hidden` у ряда.
- Число в карточке — `white-space:nowrap`, шрифт через `clamp(14px,2vw,22px)`.
- Не влезает → меняй раскладку (перенос, шире колонка, меньше отступы).
  **Данные, которые просил пользователь, не удаляй** — ни часы, ни строки.
- Пустое место в колонке — это не брак. Не набивай его выдуманным содержимым.
- На кадрах screenshot смотри сам; правь только то, что ясно видишь как брак.
  Машинная проверка точно измеряет обрезку и скрытые элементы — если она чистая,
  «обрезано» тебе, скорее всего, показалось.
